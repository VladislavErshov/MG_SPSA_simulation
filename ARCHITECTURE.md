# Архитектура симулятора

Архитектура симулятора состоит из двух основных слоёв: **оптимизатор** (SPSA или обычный градиентный спуск) и **физическая модель дрона**. Они работают в замкнутом цикле: оптимизатор выдаёт управляющее воздействие, физика применяет его с учётом инерции, и процесс повторяется.

По умолчанию используется SPSA, но через `DroneConfig.optimizer_type` можно выбрать `"gd"` — обычный градиентный спуск. Это позволяет сравнить стохастический одновременный метод с детерминированным вычислением градиента.

## 1. Слой оптимизации — SPSA (`src/drone_simulator/optimizers/spsa.py`)

### Базовый алгоритм (`MixedVariableSPSA`)

Каждый шаг оптимизатор хранит вектор параметров `theta = [speed, direction]` и обновляет его по стохастическому градиенту:

1. **Возмущение**: генерируется случайный вектор `delta` из `±1` (распределение Бернулли)
2. **Оценка градиента**: функция потерь вычисляется в двух точках — `theta + c*delta` и `theta - c*delta`. Градиент оценивается по формуле одновременного возмущения:
   ```
   g ≈ [L(theta + c*delta) - L(theta - c*delta)] / (2c*delta)
   ```
3. **Обновление**: `theta_new = theta - a_n * g`, где шаг `a_n = a / n^alpha` убывает со временем
4. **Клиппинг**: скорость ограничивается `[speed_min, speed_max]`, угол нормализуется через `arctan2(sin, cos)`

### Специализированный оптимизатор (`TargetFollowingSPSA`)

Наследуется от базового, но с динамической функцией потерь `_dynamic_loss`. Она состоит из пяти компонентов:

| Компонент | Что делает |
|---|---|
| **Distance to target** | `norm(next_position - target)` — основная цель, двигаться к точке |
| **Obstacle avoidance** | Барьерная функция: резкий штраф при столкновении, мягкий отталкивание на расстоянии |
| **Speed smoothness** | Штраф за резкое изменение скорости относительно предыдущего шага |
| **Direction smoothness** | Штраф за резкие повороты (с корректной обработкой wrap-around углов) |
| **Energy efficiency** | Штраф за высокую скорость, поощряет экономичность |

Веса каждого компонента передаются через `kwargs` при вызове `step_with_state()`.

## 1b. Сравнение: SPSA vs Обычный градиентный спуск (`src/drone_simulator/optimizers/gradient.py`)

Для сравнения реализован обычный градиентный спуск (`TargetFollowingGD`) с теми же компонентами loss-функции.

### Как работает GD

Вместо одновременного стохастического возмущения, GD вычисляет градиент **детерминированно** через центральные конечные разности:

```
for i in 0..d-1:
    grad[i] = (L(theta + eps*e_i) - L(theta - eps*e_i)) / (2*eps)
theta = theta - lr * grad
```

Где `e_i` — единичный вектор по i-й координате.

### Ключевые различия

| Аспект | SPSA | Gradient Descent |
|---|---|---|
| **Вычисления loss на шаг** | 2 (независимо от размерности) | 2*d = 4 (для d=2) |
| **Характер градиента** | Стохастический (случайное возмущение) | Детерминированный |
| **Сходимость** | Шаг убывает: `a_n = a / n^alpha` | Постоянный `lr` |
| **Чувствительность к шуму** | Выше (одновременное возмущение) | Ниже (точный численный градиент) |
| **Масштабируемость** | Лучше при большом d | Хуже при большом d |

### Практическое наблюдение

При d=2 разница в числе вычислений loss невелика (2 vs 4), поэтому GD может показывать более стабильную сходимость. SPSA же имеет преимущество в стохастичности — случайные возмущения иногда помогают выбраться из локальных минимумов. В данном симуляторе оба метода работают схоже, но GD требует тщательного подбора `lr`, иначе может расходиться.

## 2. Слой физики — Дрон (`src/drone_simulator/core/drone.py`)

### Конфигурация (`DroneConfig`)

Определяет физические ограничения: массу, максимальную тягу, максимальную скорость, коэффициент инерции (`inertia_coefficient` от 0 до 1) и время отклика.

### Состояние дрона (`Drone`)

На каждом шаге дрон хранит:
- `position`, `velocity`, `acceleration` — текущие кинематические величины
- `trajectory`, `speed_history`, `direction_history`, `time_history` — история для анализа
- `optimizer` — экземпляр `TargetFollowingSPSA` или `TargetFollowingGD`, встроенный в дрон. Тип выбирается через `DroneConfig.optimizer_type`

### Цикл управления (`Drone.step()`)

Каждый шаг симуляции (dt = 0.05 с) выполняется в три фазы:

1. **Оптимизация** (`_compute_desired_control`):
   - Обновляется состояние оптимизатора: текущая позиция, цель, препятствия
   - Запускается один шаг SPSA с заданными весами loss-функции
   - Получаем желаемые `speed` и `direction`

2. **Применение с инерцией** (`_apply_control_with_inertia`):
   - Желаемое направление преобразуется в вектор скорости
   - Применяется фильтр инерции: `v_new = inertia * v_old + (1 - inertia) * v_desired`
   - Если полученная скорость превышает `max_speed` — нормализуется
   - Это ключевой момент: дрон не мгновенно меняет скорость, а плавно "разгоняется" или "тормозит"

3. **Обновление позиции**:
   - `position += velocity * dt`
   - Обновляется время, сохраняется история

## 3. Слой симуляции (`DroneSimulator`)

Управляет множеством дронов:

- `SimulationConfig` задаёт длительность, шаг `dt`, интервалы оптимизации и отрисовки
- `step()` — один глобальный шаг: проверяет лимит времени, обновляет все дроны, увеличивает счётчик
- `run()` — основной цикл `while self.step()`, который:
  - Делегирует отрисовку `SimulationVisualizer`
  - Собирает кадры для анимации (если `save_animation=True`)
  - По окончании выводит статистику (финальная позиция, расстояние до цели, длина траектории)

## 3b. Слой визуализации (`src/drone_simulator/visualization/simulation_viz.py`)

`SimulationVisualizer` инкапсулирует всю работу с matplotlib:

- `setup_realtime()` — создаёт интерактивное окно 2×2 с графиками
- `update()` — обновляет 4 панели (траектория, скорость, направление, loss) в реальном времени
- `capture_frame()` — рендерит кадр для GIF
- `show_final()` — строит итоговый комплексный 2×3 график по окончании симуляции

Отделение визуализации от движка симуляции позволяет тестировать логику `DroneSimulator` без зависимости от matplotlib и упрощает замену бэкенда отрисовки.

## 4. Поток данных в замкнутом цикле

```
[Drone position, target, obstacles]
           ↓
   [TargetFollowingSPSA]
   _dynamic_loss оценивает:
   - дистанцию до цели
   - близость к препятствиям
   - плавность управления
           ↓
   [desired_speed, desired_direction]
           ↓
   [Физика с инерцией]
   v = inertia * v_old + (1-inertia) * v_desired
           ↓
   [position += v * dt]
           ↓
   (повтор)
```

## 4b. Загрузка конфигурации (`src/drone_simulator/utils/config_loader.py`)

Параметры симуляции, физики и оптимизаторов вынесены в JSON-файлы под `configs/`:

- `configs/simulation/default.json` — длительность, шаг, препятствия, физика дрона, пути к конфигам оптимизаторов
- `configs/spsa/default.json` — гиперпараметры SPSA (`a`, `c`, `alpha`, `gamma`)
- `configs/gd/default.json` — гиперпараметры GD (`lr`, `epsilon`)

`load_simulation_config()` читает эти файлы и возвращает готовые объекты `SimulationConfig`, `DroneConfig`, `SPSAConfig`, `GradientDescentConfig`, позволяя запускать симуляцию без хардкода параметров в коде.

## 5. Особенности реализации

- **Mixed-variable**: несмотря на название, в текущей реализации скорость и направление обновляются одинаково через SPSA. "Смешанность" заложена в структуре через разделение на `speed_params` и `direction_params`, но не используется по-разному
- **Нет динамической модели**: loss-функция предсказывает следующую позицию наивно — `current + speed * [cos(dir), sin(dir)]`, без учёта реальной инерции. Это означает, что SPSA оптимизирует "идеальное" управление, а физика затем накладывает на него ограничения
- **Один SPSA-шаг на такт симуляции**: оптимизатор не прогоняется до сходимости, а делает ровно один шаг градиентного спуска за кадр. Это создаёт эффект "реального времени" — дрон адаптируется к меняющейся ситуации постепенно
